# Javryn V0.2 — Implementation Plan: JavaScript Engine Integration

## 1. Executive Summary & Context

Javryn V0.1 established a stable Rust CLI and runtime lifecycle foundation (`javryn-cli`, `javryn-runtime`, `javryn-core`). V0.2 introduces real JavaScript execution by integrating a JavaScript engine behind a flexible engine abstraction layer.

---

## 2. JavaScript Engine Evaluation & Selection

### Engine Candidates Evaluated

1. **Boa Engine (`boa_engine`)** — *SELECTED*
   - **ECMAScript Conformance**: High conformance to modern ES2024 standards (Classes, Arrow functions, Promises, Closures, Map/Set, Destructuring, Modules, JSON, Math, RegExp, Template Literals, etc.).
   - **Rust Integration**: 100% native Rust, zero unsafe C/C++ bindings or external build toolchain dependencies (no CMake, C++ compiler, or Python required).
   - **Embeddability**: `boa_engine::Context` provides clean isolate-style initialization and execution.
   - **Thread Safety & Worker Suitability**: `Context` instances are self-contained. Future Javryn workers (V0.4+) can each own an independent `Context` on their dedicated thread without cross-thread lock contention.
   - **Error Handling**: Detailed `JsError` and `JsNativeError` inspection with stack trace and message formatting.
   - **License**: MIT / Apache 2.0 dual license.

2. **QuickJS (`rquickjs`)**
   - Requires C compilation of QuickJS sources. Complex native build configuration on Windows MSVC.

3. **V8 (`rusty_v8`)**
   - High performance, but massive binary overhead, heavy build requirements (gn, ninja, python), and complex C++ binding safety invariants.

### Selection Decision
**`boa_engine` (v0.20)** is selected as the primary engine for Javryn V0.2 because of its 100% native Rust implementation, seamless cross-platform build stability, robust ECMAScript feature coverage, and clean memory isolation model.

---

## 3. Engine Abstraction Architecture

To ensure Javryn does not leak engine-specific types (`boa_engine::Context`, `JsValue`, `JsError`) into `javryn-cli` or public runtime APIs, we define an **Engine Abstraction Layer** in `javryn-runtime`.

```text
                 Javryn CLI (javryn-cli)
                           │
                           ▼
              Javryn Runtime (javryn-runtime)
                           │
                           ▼
          JavaScriptEngine Trait (Abstraction)
                           │
             ┌─────────────┴─────────────┐
             ▼                           ▼
    BoaEngineAdapter             FutureEngineAdapter
    (boa_engine v0.20)             (e.g., QuickJS/V8)
             │
             ▼
      Boa Context (VM)
```

### Engine Trait Design

```rust
pub trait JavaScriptEngine: Send {
    /// Initializes the engine and registers global bindings (console API, etc.).
    fn initialize(&mut self) -> Result<(), RuntimeError>;

    /// Executes JavaScript source code associated with a canonical script path.
    fn execute(&mut self, source: &str, path: &Path) -> Result<ExecutionResult, RuntimeError>;

    /// Shuts down the engine cleanly.
    fn shutdown(&mut self) -> Result<(), RuntimeError>;
}
```

### Execution Result Type (Engine-Neutral)

```rust
#[derive(Debug, Clone)]
pub struct ExecutionResult {
    /// Indicates whether execution finished without unhandled exceptions.
    pub success: bool,
    /// Human-readable representation of the evaluation result (if any).
    pub return_value: Option<String>,
}
```

## 4. Console Bridge & Diagnostic Output

A native `console` object is registered into the JavaScript global environment during engine initialization:

- `console.log(...args)` -> Outputs formatted string to stdout (or respects quiet mode).
- `console.error(...args)` -> Outputs formatted string to stderr.
- `console.warn(...args)` -> Outputs formatted string to stderr (prefixed or warning style).
- `console.info(...args)` -> Outputs formatted string to stdout.

Console outputs are integrated with Javryn's runtime mode (`--quiet`, `--verbose`, `--debug`):
- In `--quiet` mode: `console.log` and `console.info` outputs are suppressed; `console.error` and `console.warn` remain active.

---

## 5. Error Architecture & Exit Codes

JavaScript errors are converted into structured `RuntimeError` instances:

1. **`RuntimeError::JavaScriptSyntax`**
   - Raised when code fails parsing/compilation.
   - Includes script path, line, column, and description.
   - Maps to `ExitCode::InvalidInput` (2).

2. **`RuntimeError::JavaScriptExecution`**
   - Raised when an unhandled JS exception is thrown (`throw new Error(...)`, `TypeError`, `ReferenceError`, etc.).
   - Captures exception name, message, stack trace, and location.
   - Maps to `ExitCode::RuntimeFailure` (5).

3. **`RuntimeError::EngineInitialization`**
   - Maps to `ExitCode::InitializationFailure` (4).

No JS error will ever cause a Rust panic.

---

## 6. Script & Module Strategy

- **File execution**: The runtime loads source code from `.js` or `.mjs` files using UTF-8 decoding. Non-UTF-8 source files trigger a clear `RuntimeError::ScriptUnreadable` or `RuntimeError::InvalidScriptEncoding`.
- **ES Modules (`.mjs`)**: Source is evaluated within module context. Full static filesystem module resolution (`import ... from "./other.mjs"`) will be documented with exact engine capabilities.

---

## 7. Security Boundary

In V0.2:
- JavaScript has **NO** access to Node.js APIs (`fs`, `net`, `http`, `child_process`, `process`, `require`, `Buffer`).
- JavaScript has **NO** capability to spawn processes, execute shell commands, or access environment secrets.
- JavaScript is restricted to standard ECMAScript built-in objects (`Object`, `Array`, `Function`, `Promise`, `Math`, `JSON`, `Map`, `Set`, `Date`, `RegExp`, `Reflect`, `Proxy`, etc.) and the host-provided `console` API.

## 8. Implementation Phases

1. **Phase 1: Architecture & Dependencies**
   - Add `boa_engine` to `javryn-runtime/Cargo.toml`.
   - Update `javryn-core` with JS error variants (`JavaScriptSyntax`, `JavaScriptExecution`, `EngineInitialization`).

2. **Phase 2: Engine Abstraction & Adapter**
   - Create `crates/javryn-runtime/src/engine/mod.rs` defining `JavaScriptEngine` trait and `ExecutionResult`.
   - Implement `BoaEngineAdapter` in `crates/javryn-runtime/src/engine/boa.rs`.

3. **Phase 3: Console Bridge**
   - Implement native host function bindings for `console.log`, `console.error`, `console.warn`, `console.info`.

4. **Phase 4: Runtime Integration**
   - Wire `BoaEngineAdapter` into `Runtime::initialize()` and `Runtime::execute()`.
   - Read script file source and pass to engine.

5. **Phase 5: JavaScript Compatibility Test Suite**
   - Create `tests/javascript/` with 15 test scripts:
     `01_variables.js`, `02_functions.js`, `03_arrays.js`, `04_objects.js`, `05_classes.js`, `06_closures.js`, `07_loops.js`, `08_exceptions.js`, `09_json.js`, `10_math.js`, `11_strings.js`, `12_maps_sets.js`, `13_promises.js`, `14_unicode.js`, `15_modules.mjs`.

6. **Phase 6: Integration, Benchmarks & Documentation**
   - Update CLI tests (`javryn examples/hello.js`, `javryn examples/compute.js`).
   - Create mock engine adapter for failure testing.
   - Update benchmarks and write `docs/JAVASCRIPT_ENGINE.md`.

7. **Phase 7: Final Quality Gates**
   - Run `cargo fmt`, `cargo check`, `cargo clippy`, `cargo test`, `cargo build --release`.
