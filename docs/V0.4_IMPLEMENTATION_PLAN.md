# Javryn V0.4 — Independent JavaScript Workers Implementation Plan

> **Milestone Objective**: Evolve Javryn into a multi-context JavaScript runtime with independent worker threads, isolated VM contexts, message passing, serialization, worker lifecycle management, and failure isolation.

---

## 1. Current Architecture (V0.3 Baseline)

In V0.3, Javryn is a single-threaded asynchronous runtime:
* **Single Thread**: JavaScript execution occurs on a single thread.
* **Single VM Context**: Single `boa_engine::Context` per runtime.
* **Event Loop**: Single-threaded `EventLoop` driving Promise microtasks (`context.run_jobs()`) and macro-task timers (`TimerQueue`).
* **Host APIs**: `console`, `setTimeout`, `clearTimeout`, `setInterval`, `clearInterval`, `queueMicrotask`.

---

## 2. Target V0.4 Worker Architecture

V0.4 introduces multi-context execution via isolated worker threads:

```text
                        Javryn Runtime
                              │
                      Worker Manager
                              │
             ┌────────────────┼────────────────┐
             ▼                ▼                ▼
         Worker 1         Worker 2         Worker N
             │                │                │
       ┌─────┴─────┐    ┌─────┴─────┐    ┌─────┴─────┐
       │ JS Engine │    │ JS Engine │    │ JS Engine │
       │ Boa VM    │    │ Boa VM    │    │ Boa VM    │
       ├───────────┤    ├───────────┤    ├───────────┤
       │ EventLoop │    │ EventLoop │    │ EventLoop │
       └─────┬─────┘    └─────┬─────┘    └─────┬─────┘
             │                │                │
             └────────────────┼────────────────┘
                              │
                        Message Channels
```

### Core Design Rules
1. **VM Isolation**: Every worker owns an independent `BoaEngineAdapter` and `boa_engine::Context`. JS heap objects are NEVER shared across worker boundaries.
2. **Thread Ownership**: Each worker runs on its own dedicated OS thread (`std::thread`). Boa `Context` lives strictly within its designated worker thread (preserving thread safety and avoiding `Send` requirement on `Context`).
3. **Event Loop Integration**: The worker event loop multiplexes:
   - Promise microtasks (`context.run_jobs()`)
   - Due timers (`TimerQueue`)
   - Incoming worker messages (`WorkerMessage`)
   - Shutdown signals
4. **Wakeup Mechanism**: Use thread channels (`std::sync::mpsc::channel`) with deadline-calculated timeouts so worker threads sleep when idle and instantly wake up upon incoming message, timer deadline, or shutdown request (Zero busy polling!).

## 3. Worker Lifecycle & State Machine

Each worker progresses through a strict state machine:

```text
Created ──► Starting ──► Running ──► Stopping ──► Stopped
                            │
                            └──────► Failed
```

* **Created**: Worker handle allocated, IDs assigned.
* **Starting**: OS thread spawned; initializing `BoaEngineAdapter`, event loop, and host bindings (`Worker`, `postMessage`, `onmessage`, `onerror`).
* **Running**: Startup handshake completed successfully (`WorkerResponse::Ready`). Worker processing event loop and messages.
* **Stopping**: Shutdown requested via `terminate()` or `WorkerManager` shutdown.
* **Stopped**: Worker thread cleanly joined, VM resources freed.
* **Failed**: JS unhandled exception, initialization error, or panic encountered. Isolated from other workers.

## 4. Message Transport & Protocol

### Message Channel
* Communication between `WorkerManager` / Main Thread and `Worker` threads uses bi-directional `std::sync::mpsc` channels.

### Data Protocol
* **`WorkerMessage`** (Main $\to$ Worker):
  - `Execute { script_path: PathBuf }`: Loads and executes initial script in worker.
  - `PostMessage { request_id: RequestId, data: JsMessage }`: Delivers JS message payload to worker's `onmessage` handler.
  - `Shutdown`: Requests graceful worker event loop termination.
* **`WorkerResponse`** (Worker $\to$ Main):
  - `Ready { worker_id: WorkerId }`: Startup handshake confirmation.
  - `PostMessage { request_id: RequestId, data: JsMessage }`: Worker posted a message via `postMessage()`.
  - `Error { worker_id: WorkerId, error: String }`: JS exception or runtime failure.
  - `Stopped { worker_id: WorkerId }`: Worker thread terminated.

## 5. Message Serialization (`JsMessage`)

JavaScript objects are serialized into a thread-safe, owned Rust representation:

```rust
#[derive(Debug, Clone, PartialEq)]
pub enum JsMessage {
    Null,
    Undefined,
    Boolean(bool),
    Number(f64),
    String(String),
    Array(Vec<JsMessage>),
    Object(std::collections::BTreeMap<String, JsMessage>),
}
```

* Conversion functions (`JsValue` $\leftrightarrow$ `JsMessage`) safely convert between Boa JS engine values and `JsMessage`.
* Unsupported types (Functions, Symbols, Promises, Native objects) return a clear serialization error without panicking or corrupting memory.

## 6. JavaScript Host Worker API

Exposed in global scope for main script and worker scripts:

```javascript
// Worker creation
const worker = new Worker("./workers/child.js");

// Message sending
worker.postMessage({ count: 42 });

// Message handler
worker.onmessage = (event) => {
    console.log("received:", event.data);
};

// Error handler
worker.onerror = (error) => {
    console.error("worker error:", error);
};

// Termination
worker.terminate();
```

Inside child worker scripts:
```javascript
onmessage = (event) => {
    console.log("child received:", event.data);
    postMessage(event.data * 2);
};
```

---

## 7. Failure & Panic Isolation

* **JS Exception Isolation**: Exception in Worker 1 does not crash Worker 2 or main process.
* **Panic Isolation**: Worker thread execution is wrapped in `std::panic::catch_unwind`. A panic marks the specific worker state as `Failed` and notifies `WorkerManager` without process crash.
* **Thread Cleanup**: All thread handles are explicitly owned and joined upon termination (`JoinHandle`). No detached threads or resource leaks.

## 8. Implementation Steps

1. **`javryn-core`**: Add worker error variants to `RuntimeError` (`WorkerCreation`, `WorkerInitialization`, `WorkerCommunication`, `WorkerSerialization`, `WorkerExecution`, `WorkerShutdown`, `WorkerFailed`).
2. **`javryn-runtime/src/workers/`**:
   - `id.rs`: `WorkerId`, `RequestId`.
   - `message.rs`: `JsMessage` serialization/deserialization logic.
   - `worker.rs`: `Worker` thread loop, event loop multiplexing, and lifecycle management.
   - `manager.rs`: `WorkerManager` pool and channel coordinator.
   - `host.rs`: JS bindings for `Worker`, `postMessage`, `onmessage`, `onerror`, `terminate`.
3. **Integration with `BoaEngineAdapter` & Event Loop**: Expose message channel polling in worker event loop.
4. **JS Test Suite & Examples**:
   - `tests/javascript/workers/basic_worker.js`
