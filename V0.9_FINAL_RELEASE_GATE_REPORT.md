## 12. Security Boundary & Documented Model

1. **Memory Isolation**: Each worker runs an isolated `boa_engine::Context` on a dedicated OS thread. Heap memory is unshared.
2. **Serialization Boundary**: `JsMessage` enforces serializable value transmission. Functions and non-serializable objects reject safely without thread channel poisoning.
3. **Host Resource Access**: Javryn JavaScript contexts retain standard ECMAScript host bindings (`console`, timers). Javryn is **NOT a security sandbox** against local filesystem or process access.

## 14. Known Limitations

1. **Javryn is not a hardened sandbox**: Script execution is isolated per thread heap, but ECMAScript host functions still have native access permissions of the parent process.
2. **Panic Boundary**: Worker thread panics are caught via `catch_unwind` and evicted from the pool; however, Rust code within custom host functions must avoid triggering uncatchable aborts.
